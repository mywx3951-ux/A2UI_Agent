# 09 多轮增量更新

- 阶段：9 / 16
- 目标：验证基于当前协议做组件 / 数据 / 主题微调
- 执行方式：手工（需要两轮对话）
- 当前状态：已实现

## 操作步骤

1. 先完成 `07-complex-page`，得到一个天气页面
2. 不要刷新页面
3. 直接继续发送下面的提示词

## 发给 AI 的提示词

```text
在刚才的天气页面上，把刷新按钮改成蓝色，并增加一个「湿度」字段。
```

## 预期行为

前端会把当前完整 A2UI 协议作为 `currentProtocol` 发给服务端，服务端提示词要求：

- 只输出发生变化的消息
- 保持 surfaceId 和组件 id 稳定
- 不重复未修改的组件

预期第二轮返回的补丁可能包含：

```text
surfaceUpdate    # 修改按钮或新增湿度组件
dataModelUpdate  # 新增湿度数据
beginRendering   # 主题样式变化时
```

## 检查项

- [ ] 第二次请求携带了 `currentProtocol`
- [ ] 返回的消息数量明显少于首次生成
- [ ] 原页面内容仍然存在
- [ ] 新增了湿度字段
- [ ] 刷新按钮样式发生变化
- [ ] 聊天区显示「已更新界面」
- [ ] 页面没有整体闪烁或重新构建

## 评分

| 项 | 分值 |
| --- | --- |
| 协议合法 | 20 |
| 增量范围 | 25 |
| 原内容保留 | 20 |
| 修改正确性 | 20 |
| 渲染稳定 | 15 |

## 当前实现细节

- 前端保留 `parserRef` 和 `protocolRef`
- 增量模式下不调用 `resetRender`
- 新消息直接喂给同一个 Parser
- Store 按 component id 合并
- 代码区展示合并后的完整协议

## 注意事项

如果模型仍然返回全量组件，页面依然能正确渲染，但会失去增量更新的 token 优势。记录时应注明：

```text
模型返回了全量消息，而非最小补丁
```
